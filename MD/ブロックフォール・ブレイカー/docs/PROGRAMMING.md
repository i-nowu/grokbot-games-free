# ブロックフォール・ブレイカー プログラム（GBプログラマー）

## ビルドとテスト
```sh
source tools/env.sh
make build                 # → build/game.bin（仮素材の不足分作成 → フォント → texts.h → SGDK）
python3 test/playtest.py   # 画面なし通しテスト → test/shots/*.png, test/contact_sheet.png
```
- `make build` は `-mstrict-align` を付けてコンパイルする。付けないと gcc 14 が奇数番地へのワード書き込みを作り、実機/エミュで ADDRESS ERROR になった（下の「注意」）。
- 画面の文は `scenario/game.txt`（`ID>文`）。`tools/gentext.py` が `game/src/texts.h` の `TX_ID` にする。字を足したら `make build` だけでよい（中で `make font` も流れる）。
- 起動時の注意文は `TX_notice1〜5`。1文1行、一字も変えない。どの文も 38 字以内なので折り返しなし（GrokBOT の途中で切れない）。

## 画面の流れ（main.c）
注意書き → タイトル（クリアモード / エンドレス / ギャラリー）→ キャラ選択（ミカ / ゴウ）→ ステージ → クリア表示 → ごほうび絵（クリアモードのみ）→ 次のステージ … ステージ10のごほうび絵 → エンディング（盤面が下から光って消える → 文）→ スタッフ → 注意書き → タイトル。
ゲームオーバー: スコアとハイスコア → START でタイトル。ハイスコアと解放した絵は電源を切るまで保持。

## 盤面
- 10列×23段（0〜22）+ パドル段。上から敵の隊列（5列×3〜5段、ステージ4〜は最上段が銀）、ピースは「いちばん下の敵の1段下」から出る。
- 敵の色→ピース: 赤=棒2/棒3、青=角/四角、黄=点/爆弾(1/4)、銀=鉄、ボス=どれでも。
- 列消し段数ぶんボール（最大6個）。ボールはブロックを壊し（鉄は壊れない）、敵に当たると倒す（銀は2回）。ボス（ステージ5・10、2x2マス）は10回。
- パドルは自動追従、C を押している間は十字キーでパドル。ボールを落としても失敗ではない。
- UFO: ときどき最上段を横切る。当てると 500 点 + 一番下の段を消す。
- ゲームオーバー: ピースが出られない / 敵が積んだブロックに触れる・最下段に着く / 敵がピースに乗って押し込めない。
- 点数は仕様 5章どおり（れんさ: ボール1個で3体目から2倍、クリアで残り時間×10、時間は180秒）。
- 表示: 盤面・敵・枠は BG_A のタイル（変わったマスだけ書く）、背景絵は BG_B、パドル(8x8×3)・ボール・UFO はスプライト（最大10個、1ライン20個に届かない）。
- エンドレス: ステージ10以降は速さ最大のまま続き、5の倍数はボス。ごほうび絵は出ない。

## デバッグ操作（テスト用）
ポーズ中（START）に C を押しながら A = 敵全滅（ステージクリア）、C を押しながら B = ボール1個。
テストが読む変数 `g_dbg`（番地は `game/out/release/symbol.txt`）: magic(B10C), scene, stage, enemies, balls, lines, mode, chara, score, hiscore, unlocked[2], gameover。

## 素材の差し替え（置けばそのまま入る）
`game/res/resources.res` が読む。`tools/gen_placeholders.py` は **無いファイルだけ** 仮素材を作る（本番素材を上書きしない）。

| ファイル | 大きさ / 形式 | パレット | 用途 |
|---|---|---|---|
| `game/res/gfx/tiles.png` | 256x8、16色インデックス PNG、8x8 タイル 32 枚を横に並べる（並びは下） | PAL1（この PNG のパレット） | 盤面タイル・スプライト |
| `game/res/gfx/title.png` | 320x96（幅320、高さ自由 ≤ 120）16色 | PAL2 | タイトルのロゴ（2段目から表示） |
| `game/res/gfx/bg1.png` `bg2.png` `bg3.png` | 320x224 16色 | PAL2 | ステージ1〜3 / 4〜7 / 8〜10 の背景（BG_B、盤面の後ろ）|
| `game/res/gfx/ending.png` | 320x224 16色 | PAL2 | エンディング |
| `game/res/gfx/face_mika.png` `face_gou.png` | 64x64 16色 | PAL2 / PAL3 | キャラ選択 |
| `game/res/reward/mika01〜10.png` `gou01〜10.png` | 256x160 16色 | PAL2 | ごほうび絵・ギャラリー（**いまは仮。GB企画の確認後に置く**）|
| `res/sound/bgm_*.vgm` `se_*.wav` | GB音楽の本番（docs/SOUND.md）| — | 組み込み済み |

- 色0は透明。1枚の絵の固有タイルは 700 枚以下（VRAM の割り当て。320x224 全部違うと 1120 枚で入らない）。
- tiles.png の並び: 0 空(透明) / 1 点 / 2 棒2 / 3 角 / 4 棒3 / 5 四角 / 6 爆弾 / 7 鉄 / 8 枠 / 9-10 赤敵2コマ / 11-12 青 / 13-14 黄 / 15-16 銀 / 17-20 ボス(左上・右上・左下・右下) / 21 UFO / 22 パドル / 23 ボール(カーソルにも使う) / 24 爆発 / 25 銀の傷つき / 26 星 / 27-31 空き。
- 音: 曲は `XGM2_play`、効果音は `XGM2_playPCM` を PCM CH2 / CH3 交互（CH1 は空け）。曲の割り当て: タイトル=title、ステージ1〜3=stage1、4〜7=stage2、8〜10=stage3、5・10=boss、エンディングとギャラリー=ending、ゲームオーバー=gameover。

## 注意（環境）
- m68k-linux-gnu-gcc 14 は `-m68000` でも既定で厳密な境界合わせをしない。構造体の2つのバイトをまとめて奇数番地にワードで書くコードが出て、ADDRESS ERROR で止まった。ゲームは `EXTRA_FLAGS=-mstrict-align` と構造体の u16 化で直した。SGDK の `libmd.a` も同じフラグなしで作られているので、作り直すほうが安全。
- エミュレーター（mdrun）は3ボタンパッドとして動くので、MODE/X/Y/Z は読めない。

## 実プレイの確認（v2）
- `python3 test/bot.py [--stages 5] [--seed-wait N]`: デバッグ操作なしで RAM（盤面・ピース・敵）を読み、置き場所を評価してボタンで遊ぶボット。結果は各ステージの秒数・点・最高の積み高さ・ライン。画面は `test/shots/bot_*.png`。
- `test/mdlib.py`: テスト用の対話型ドライバ（1フレームずつ進めて g_dbg を読む）。`test/playtest.py` は場面の変化を待つ形にした（絵の読み込みが長くてもずれない）。
- 直したこと: 盤面の描き直しが重くて処理落ちし、ゲームが半分の速さ（30fps）で動いていた → 変わったマスだけ速く判定するよう直して 60fps に。
- 調整: 敵は横に1歩 `eint = 56 - 3×レベル` フレーム、壁に `dint` 回（レベル1〜3: 4回、4〜7: 3回、8〜10: 2回、エンドレス11〜: 3回）当たると1段下がる（前は毎回下がっていた）。
- ごほうび絵などの一枚絵の色0は透明でなく一番暗い色なので、その画面では背景色（PAL0 色0）を絵の色0に合わせる。

## 難しさ（SPEC 14章、v2.4）
- ボールは敵とブロックに合計8回当たると消える。同時に4個まで。
- 自動パドルが受ける確率: 1〜2: 100%、3〜4: 90%、5〜6: 80%、7〜8: 70%、9〜: 60%。ボールが落ちてくるたびに1回判定。C を押している間（手動）は必ず受ける。
- 追加の調整: 次のピースが出るまで ステージ1〜3: 45、4〜6: 30、7〜: 20 フレーム。敵が下がるのは壁に ステージ1〜3: 5回、4〜7: 3回、8〜10: 2回当たったとき。
- 確認: `test/bot.py` は自動パドルだけ（C は使わない）。いつも「すぐ落とす」で置く、気軽に遊ぶ人に近い想定。12通りの乱数で 1〜3 は全部クリア、7〜10 で負けることがある（結果は test/bot_results.json）。
- ボットのつまずき対策: ごほうび絵から戻るときの START が二重に入ってポーズになることがあったので、g_dbg に paused を足して読む。

## 製品版とデバッグ版
- `make release` → `build/game.bin`（= `build/blockfall_breaker.bin`）。デバッグ操作なし。
- `make debug` → `build/game_debug.bin`（`-DDEBUG_KEYS`。ポーズ中 C+A=敵全滅、C+B=ボール1個）。`test/playtest.py` はこちらを使う。
- 2つは変数の番地がちがうので、`build/game.symbol.txt` / `build/game_debug.symbol.txt` をテストが ROM 名から選ぶ。続けて作るときは最後に `make release` を流すこと（game/out は最後に作った方になる）。
- `python3 test/release_check.py [ROM]`: 注意書きの字を画面から読み取って5文と一字ずつ照合、タイトル・キャラ選択・ステージ1、デバッグ操作が効かないことを確かめる。
