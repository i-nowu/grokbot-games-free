## 2. ハード（開発: devkitARM + libtonc、テスト: mGBA）
- 画面240x160、15ビット色。Mode 0（タイルBG 4枚）を使う。
- BGパレット16色x16本、OBJパレット16色x16本（または256色1本）。
- OBJは128個。1ラインの上限は描画サイクル1210（8x8なら128個全部出せる）。
- VRAM 96KB。Mode 0ではBG用64KB、OBJ用32KB。Mode 3〜5（ビットマップ）ではOBJ用が16KBに減る。ROMは最大32MB、今回は4MB以内を目安。セーブなし。
- 音: PSG 4ch（矩形2、波形1、ノイズ1）＋ DirectSound（8ビットPCM 2ch、タイマーとDMAで送る）。

## 3. 画面
- 1マス6x6で盤面を60x144（10x6、24x6）に置く。上下に8pxずつ余白。決定。
  - 6x6はタイル境界とずれる（1タイルに最大4マス）ので、CPUで4bppタイルに描く（タイルの中にビットマップを描くソフト描画）。盤面8x18=144タイル（4,608バイト）。毎フレームDMAで全部送ってもよい。
  - ブロック7色は16色パレット1本に入るので、色はぶつからない。落下ピースも盤面のタイルに描く。
- ボール、パドル、敵、UFO、爆発はOBJ（敵はPCE版どおりBGでもよい）。
- 右側（約180px）に情報欄（スコア、ハイスコア、ステージ、タイム、ライン、ネクスト、キャラ名）。
- 背景はBGもう1枚。文字はBG。

## 4. 操作
- 回転: A（右）／B（左）。十字: 移動、下＝速く、上＝すぐ落とす。
- パドルを手で動かす: Rを押している間（Lでも可）。
- ポーズ: START。ゲームオーバー画面はSTARTで進む。
- リセット（A+B+START+SELECT）はタイトル画面でだけ効く。

## 5. 音
- PCE版の曲を編曲し直す。メロディと和音はPSG（矩形2ch＋波形1ch）、ベースや厚みはDirectSoundで足す（DirectSoundは片方を効果音専用にしてもよい）。
- 効果音は曲と取り合わない（専用chを決める）。
- 効果音がBGMに負けないよう、音量の釣り合いをGB音楽が確かめる。

## 6. ご褒美の絵
- PCE版の20枚（ミカ10、ゴウ10）を使い、240x160以内（目安240x150）に縮めて色を減らし直す。ギャラリーとご褒美の絵の画面はMode 4（240x160、256色、1枚37.5KB）で出す。このときOBJ用VRAMは16KBになるが、この画面のOBJは少ないので足りる。
- 守ること（PCE版6章とMD版12章と同じ）: 2人とも成人に見える。裸、下着、性的なポーズはなし。最後は大人の普通の水着まで。子どもっぽい顔や体、制服、スクール水着はなし。実在の人物や既存キャラに似せない。アニメ調を最優先。
- 縮めた20枚は1枚ずつ企画が確認してから入れる（顔がつぶれて子どもっぽく見えないか、も見る）。

## 7. 合格の条件
- 注意文が上の5行のとおり（画面写真で一字ずつ照合）。
- 注意文 → タイトル → キャラ選び → ゲーム → エンディング → 注意文 → タイトルまで通して動く。
- 完成版にデバッグキーが残っていない。
- 難しさのテスト（PCE版8章と同じ）: SELECT相当の手動受けを入れた自動プレイで24通り中、ステージ1〜3は全部クリア。7面以降でときどき負ける。自動パドルだけの結果は参考値として記録。
- ご褒美の絵20枚がゲーム内で確認画像と同じに出て、企画の確認を通っている。
- mGBAで通して動く。

- 2026-10-15 決定（参謀）: ヘッダーの起動ロゴ欄は空にし、任天堂ロゴのデータは入れない。合格条件はmGBAで起動して動くこと。実機確認とgbafixとの一致確認はしない。READMEに「エミュレーター向け」と書く。

- 2026-10-15 合格条件の変更（8章を上書き）: (1) 共通のゲームの中身（bfb-core）がPCE版と突き合わせてずれ0。(2) 自動パドルのボットが24通りすべてで1〜3面をクリア。手動パドルのボットは参考扱いで、負けた面を毎回報告する。理由: 処理の遅れがない機種ではボットの入力タイミングが変わり、同じseedでも展開が変わるため。

- 2026-10-15 GB企画決定: 条件2を「タイトルでの実際のシード値で固定した24個(全機種共通)について、PCEと同じ入力を与えて全24回の結果(クリア面・負けた面・スコア)がPCEと一致すること」に変更。クリア数そのものは問わない。
