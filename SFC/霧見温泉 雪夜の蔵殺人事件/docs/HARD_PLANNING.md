# SFCで大変だったところ（企画：GB企画）

## 1. 話を一から作ること
GBとFCの「グンマー教の野望」はアクションで、ルールと数字を決めれば遊びになりました。今回の推理アドベンチャーは、話と人物とトリックを全部一から考える必要がありました。コマンドの選び方は昔の名作の形を借りましたが、それ以外はオリジナルです。
- 手がかりがどれか1つ欠けても、話のつじつまが合わなくならないように組みました。
- 時刻や天気が手がかりになるので、一覧表を作って、セリフと食いちがわないかを何度も見直しました。

## 2. どの順番で調べても詰まらないようにすること
アクションでは難しさの調整が中心でしたが、アドベンチャーでは「何をすれば次の章へ進めるか」をはっきりさせる必要がありました。
- 章ごとに、進むために必要なフラグを3つ前後に絞りました。
- 迷ったときに相棒を呼ぶと、まだ足りないことに合わせてヒントが変わるようにしました。
- 犯人をまちがえてもゲームオーバーにせず、やり直せるようにしました。

## 3. 途中で入った大きな変更
作っている途中で、舞台を群馬にすることと、ミニゲームを2つ（ホームランと新幹線）入れることが決まりました。
- 話の骨組みは変えずに、地名、方言、名物を入れて直しました。
- ミニゲームは「クリアしなくても本編が進む」おまけにして、詰まらない作りを崩さないようにしました。

## 4. 台本を「データ」として書くこと
GB・FCでは画面の文字が少なかったのですが、今回はセリフが300行近くあります。プログラマーが決めた台本の書き方に合わせて書き、その台本からROMのデータと使う字の一覧が作られます。
- 1行16字の窓に収まるように、言葉の区切りを考えて改行しました。
- 書き方の決まりにない場面（オープニング、だれにでも当てはまる「みせる」）は、チームに相談して読み込めるようにしてもらいました。

## 5. GB・FCとのちがい
- GB・FC：ルール、ステージ、数字の調整が中心。文字は少なめ。
- SFC：話、セリフ、フラグの設計が中心。絵と音の量も多く、担当の間でデータの受け渡しをきちんと決める必要がありました。
- 確認の仕方も変わりました。クリアできるかどうかだけでなく、セリフが正しい章で出るか、どの順番でも進めるかを、通しテストで確かめました。
