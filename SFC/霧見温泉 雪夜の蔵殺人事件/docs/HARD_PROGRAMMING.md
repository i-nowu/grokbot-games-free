# SFCで大変だったところ（プログラム担当）

## 1. 画面を2枚重ねて、絵と文字を分けた
SFCでは背景を何枚も重ねられます。1枚目に16色の一枚絵、3枚目に4色の文字窓をのせました。絵を変えても文字を書き直さなくてよくなり、会話の途中で場面が変わっても画面がちらつきません。そのかわり、VRAMのどこに何を置くかを、GBグラフィックさんと何度もそろえる必要がありました。

## 2. 日本語の文章を少ない字で出す
ROMに入れる字は、台本で使う字だけにしぼりました。文章は「字の番号の並び」として持ち、改行と終わりを特別な番号で表しています。台本を直すと使う字も変わるので、字の一覧からROMまで、ビルドのたびに作り直すようにしました。

## 3. 台本をそのままデータにする
GB企画さんが書いた台本を、ROMに入るデータに変える道具を作りました。「何章で」「どのフラグが立っていたら」出るセリフかを決める書き方で、いちばん悩んだのが章の条件です。最初は「その章から先ずっと」としていましたが、蔵の棚のように章ごとにセリフが変わる場所で、古い章のセリフが出てしまいました。今は、ふつうの会話は「その章だけ」、フラグを立てる場面やミニゲームは「その章から先ずっと」として、どちらも書けるようにしています。

## 4. ミニゲーム2つを同じ仕組みに入れた
ホームランと新幹線は、会話の画面とは別に、スプライトで動く画面です。会話から入って、勝っても負けても会話に戻れるようにしました。新幹線では、車両を32ドットずつすき間なく並べることと、画面の左端からはみ出した車両が右端に出てしまう不具合の直しに手間がかかりました。

## 5. 画面なしで最後まで遊ぶテスト
人の手で毎回遊ぶのは大変なので、GB仕様・環境構築さんが作ったエミュレーターを画面なしで動かす仕組みで、ボタン入力を流して最後まで遊ぶテストを2本作りました。1本はふつうの順番で進めます。もう1本は、ちがう順番で進めたり、ミニゲームをやめたり、犯人を3回まちがえたりします。台本や絵が変わるたびにこの2本を流して、詰まる場所がないか確かめました。

## GB・FC版とのちがい
- **容量:** GB・FC版は容量がきびしく、FC版では最初に読むバンクがあふれて画面が灰色のままになりました。SFC版は512KBあって、まだ3分の1ほど空いています。
- **何に時間を使ったか:** 容量に悩まなくてよくなったぶん、日本語の文章と、台本の条件の書き方に時間を使いました。
- **ゲームの種類:** アクションではなくコマンド選択のアドベンチャーなので、速さよりも「どの順番で調べても話が正しく進むか」を確かめるのが一番の仕事でした。
